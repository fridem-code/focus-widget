# Focus Widget — техническое задание

Версия: 0.1 (MVP) · Дата: 2026-10-23

## 1. Цель

Десктопный виджет для Windows: Pomodoro-таймер, который при старте фокус-сессии включает музыку для концентрации с YouTube. Виджет маленький, всегда поверх окон, живёт в трее.

## 2. Принятые решения

| Вопрос | Решение |
|---|---|
| Стек | Go + **Wails v3** (WebView2), фронтенд **Vue 3 + TypeScript + Vite** |
| Источник музыки | Официальный **YouTube IFrame Player API** (никакого yt-dlp/извлечения аудио) |
| Режим таймера | **Pomodoro**: фокус → короткий перерыв → … → длинный перерыв |
| Отображение плеера | **Два режима окна**: развёрнутый (плеер виден) и компактный (плеер скрыт, музыка на паузе) |
| Музыка на перерыве | **Настраивается**: пауза / тише / не трогать |
| Платформа MVP | Windows 10/11 x64 (macOS/Linux — не тестируем, но не ломаем намеренно) |

### Ограничения YouTube, влияющие на дизайн
- Viewport плеера **не меньше 200×200 px**, плеер нельзя скрывать или перекрывать, пока он играет ([Required Minimum Functionality](https://developers.google.com/youtube/terms/required-minimum-functionality)). Отсюда правило: **в компактном режиме музыка всегда на паузе**.
- Плееру нужен нормальный http(s)-origin и Referer, иначе ошибка 153. Спайк T0 показал, что origin Wails `http://wails.localhost` подходит, а `http://127.0.0.1` хуже: часть видео на нём не играет ([spike-results.md](spike-results.md)).
- Видео с запрещённым встраиванием или недоступные пропускаются автоматически. На практике почти всё приходит с кодом 150.
- Реклама YouTube не блокируется и не скрывается.

## 3. Функциональные требования

### 3.1 Таймер (Pomodoro)
- Фазы: `focus`, `short_break`, `long_break`. Длительности по умолчанию 25 / 5 / 15 мин, длинный перерыв после каждых 4 завершённых фокус-сессий. Всё настраивается (1–180 мин, 2–10 циклов).
- Кнопки: **Старт**, **Пауза/Продолжить**, **Пропустить фазу**, **Сброс**.
- Автостарт следующей фазы настраивается отдельно: `autoStartBreaks` (по умолчанию вкл) и `autoStartFocus` (по умолчанию выкл).
- Отображение: оставшееся время `MM:SS`, название фазы, прогресс (кольцо), индикатор циклов (●●○○).
- Время считается от дедлайна по часам (`endsAt`), а не подсчётом тиков: без дрейфа и корректно после сна ПК. Если за время сна фаза закончилась, она завершается и применяются правила автостарта (уведомление один раз).
- По окончании фазы звучит короткий звук и показывается toast Windows (оба отключаются в настройках).

### 3.2 Музыка
- **Жанр** — именованный список источников. Источник: YouTube-плейлист (`playlist`) или отдельное видео / live-стрим (`video`).
- Кнопки: **Пауза/Play музыки** (не влияет на таймер), **Следующий трек**, **Следующий жанр** (и выбор жанра из списка), **Громкость** (слайдер 0–100 + mute).
- «Следующий трек»: для плейлиста `nextVideo()`, для видео/стрима — следующий источник жанра (по кругу).
- В плейлистах по умолчанию включён shuffle (настраивается).
- Громкость, mute, текущий жанр и источник сохраняются между запусками.
- Ошибки плеера `2, 5, 100, 101, 150` (по T0 несуществующие и мёртвые ID тоже отдают `150`) → источник помечается битым на сессию, переключение на следующий; если битые все источники жанра — сообщение в UI. Ошибка `153` → понятное сообщение (диагностика конфигурации).
- Каталог жанров по умолчанию встроен в бинарник. Пользователь может переопределить его файлом `genres.json` (редактирование через UI — не MVP).

### 3.3 Связь таймера и музыки
| Событие таймера | Музыка |
|---|---|
| Старт / продолжение фокуса | play, громкость восстанавливается до пользовательской |
| Пауза таймера | pause; при продолжении играет снова, **только если играла в момент паузы** |
| Фокус → перерыв | по настройке `breakBehavior`: `pause` (по умолчанию) / `duck` (громкость → `duckVolume`, по умолчанию 20%) / `continue` |
| Перерыв → фокус (автостарт) | play + восстановление громкости |
| Перерыв → фокус без автостарта (idle) | pause |
| Сброс | pause |
| Ручная пауза музыки во время фокуса | уважается: автоматика не включает музыку до следующего явного Старт/Play |

### 3.4 Окно-виджет
- Без рамки, своя шапка с областью перетаскивания, без ресайза, по умолчанию **всегда поверх** (переключатель в шапке и в трее).
- **Развёрнутый режим** (~380×540): шапка → плеер 356×200 → таймер → управление таймером → управление музыкой.
- **Компактный режим** (~300×96): время, фаза, Старт/Пауза, Пропустить, кнопка «развернуть». При входе музыка ставится на паузу, при выходе продолжает, если играла и идёт фокус.
- Позиция и режим окна сохраняются. При запуске позиция проверяется на попадание в видимые мониторы, иначе окно ставится в правый нижний угол основного монитора.
- Крестик в шапке прячет окно в трей, выход — только из меню трея.

### 3.5 Трей
- Иконка, тултип с фазой и оставшимся временем (обновляется раз в минуту и на переходах).
- Меню: Показать/Скрыть · Старт/Пауза · Пропустить фазу · Компакт/Развернуть · Всегда поверх ✓ · Выход.
- Левый клик — показать/скрыть окно.

### 3.6 Настройки (панель в развёрнутом режиме, иконка ⚙)
Длительности фаз, интервал длинного перерыва, автостарты, `breakBehavior` и `duckVolume`, shuffle, звук/toast уведомлений, «всегда поверх».

### 3.7 Прочее
- Один экземпляр: повторный запуск показывает уже открытое окно.

## 4. Нефункциональные требования
- Размер exe ≤ 20 МБ; для WebView2 runtime используется bootstrapper Wails (на Windows 11 runtime уже есть).
- В простое без музыки CPU < 1%. С играющим плеером память определяется WebView2 + YouTube, ориентир ≤ 350 МБ.
- Холодный старт до видимого окна ≤ 2 с.
- Без телеметрии и сетевых запросов, кроме YouTube.
- Конфиг пишется атомарно (temp + rename). Битый конфиг → бэкап `config.json.bak` и дефолты, приложение не падает.
- Лог: `%APPDATA%\FocusWidget\logs\app.log` с ротацией (последние 5 файлов по 1 МБ).

## 5. Архитектура

```
┌──────────────────────── Go (Wails v3 app) ────────────────────────┐
│ internal/timer    чистый state machine Pomodoro, Clock — интерфейс │
│ internal/config   схема, дефолты, валидация, load/save, миграции   │
│ internal/catalog  жанры: embed-дефолт + override из genres.json    │
│ services/         Wails-сервисы (bindings) + эмиссия событий       │
│   TimerService    Start/Pause/Resume/Skip/Reset/State              │
│   SettingsService Get/Update                                       │
│   MusicService    Genres/Select/SaveVolume (только persistence)    │
│   WindowService   SetMode/SetAlwaysOnTop/сохранение позиции        │
│ app/              сборка приложения, окно, трей, single instance   │
└───────────────▲─────────────────────────────┬──────────────────────┘
       bindings │ (вызовы)                    │ events
┌───────────────┴─────────────────────────────▼──────────────────────┐
│ Frontend (Vue 3 + TS)                                              │
│ composables/useTimer         подписка на timer:*, вызовы сервиса   │
│ composables/useYouTubePlayer обёртка IFrame API, ошибки, очередь   │
│ lib/musicPolicy.ts           чистая функция: переход → действия    │
│ components/ TitleBar, PlayerPanel, TimerView, TimerControls,       │
│             MusicControls, CompactBar, SettingsPanel               │
└────────────────────────────────────────────────────────────────────┘
```

**Принципы**
- Источник правды по таймеру и настройкам — Go. Плеер живёт только во фронтенде (он и есть DOM-объект YouTube).
- Политика «таймер → музыка» (3.3) — чистая функция в `musicPolicy.ts` с unit-тестами. Go ничего не знает о плеере.
- `internal/*` не импортирует Wails: таймер и конфиг тестируются обычным `go test` и переживут смену фреймворка.
- **Autoplay:** WebView2 запускается с `Options.Windows.AdditionalBrowserArgs = ["--autoplay-policy=no-user-gesture-required"]`. Без этого флага `playVideo()` со звуком без клика блокируется (T0), а значит не работают «Старт» из трея и автостарт фазы. Дополнительно по клику «Старт» фронтенд вызывает `player.playVideo()` синхронно в обработчике, параллельно с `TimerService.Start()`.

### 5.1 Модель таймера

```go
type Phase  string // "focus" | "short_break" | "long_break"
type Status string // "idle" | "running" | "paused"

type State struct {
    Phase          Phase
    Status         Status
    DurationMs     int64 // полная длительность текущей фазы
    RemainingMs    int64
    CompletedFocus int   // завершённые фокусы в текущем длинном цикле
    LongBreakEvery int
}
```

Переходы:
```
idle    --Start-->  running
running --Pause-->  paused --Resume--> running
running --Expire--> next(phase); status = running, если autoStart для следующей фазы, иначе idle
any     --Skip-->   next(phase), status = idle (CompletedFocus не увеличивается)
any     --Reset-->  focus, idle, CompletedFocus = 0

Expire фокуса увеличивает CompletedFocus.
next(focus)  = long_break, если фокус завершён (Expire) и CompletedFocus >= LongBreakEvery, иначе short_break
               (пропущенный фокус не засчитывается: после Skip всегда short_break)
next(break)  = focus; выход из long_break (Expire или Skip) обнуляет CompletedFocus
```

Сколько бы дедлайн ни был просрочен (сон ПК), тик даёт **ровно один** Expire. Автостартованная следующая фаза получает полную длительность, отсчитанную от момента пробуждения. Дедлайны сравниваются по настенным часам (`time.Now().Round(0)`), поэтому время сна всегда засчитывается.

Изменение длительностей в настройках применяется к фазам в состоянии `idle` сразу, к идущей фазе — со следующей.

### 5.2 События (Go → фронтенд)
| Событие | Payload | Когда |
|---|---|---|
| `timer:state` | `State` | раз в секунду при running и на любом изменении |
| `timer:transition` | `{from: State, to: State, cause: "start"\|"pause"\|"resume"\|"expire"\|"skip"\|"reset"}` | на каждом переходе |
| `settings:changed` | `Settings` | после `SettingsService.Update` |
| `window:mode` | `"expanded"\|"compact"` | после смены режима (в том числе из трея) |

Фронтенд применяет `musicPolicy` только по `timer:transition` и `window:mode`.

### 5.3 Хранение
`%APPDATA%\FocusWidget\config.json`:
```json
{
  "version": 1,
  "timer": {
    "focusMin": 25, "shortBreakMin": 5, "longBreakMin": 15,
    "longBreakEvery": 4, "autoStartBreaks": true, "autoStartFocus": false
  },
  "music": {
    "volume": 50, "muted": false, "shuffle": true,
    "breakBehavior": "pause", "duckVolume": 20,
    "genreId": "lofi", "sourceIndex": 0
  },
  "window": { "mode": "expanded", "alwaysOnTop": true, "x": null, "y": null },
  "notify": { "sound": true, "toast": true }
}
```

`genres.json` (необязательный override, та же схема, что у встроенного):
```json
{
  "genres": [
    { "id": "lofi", "name": "Lo-fi",
      "sources": [ { "type": "video", "id": "<LIVE_VIDEO_ID>", "title": "lofi hip hop radio (live)" } ] },
    { "id": "ambient", "name": "Ambient", "sources": [ { "type": "playlist", "id": "<PLAYLIST_ID>" } ] }
  ]
}
```
Конкретные ID для встроенного каталога (4–6 жанров: lo-fi, ambient, classical, synthwave, nature/rain, jazz) подбираются в T6 и проверяются в самом IFrame-плеере. oEmbed для этого не подходит: по мёртвому стриму он отвечает 200. ID live-стримов со временем меняются (ID из первой версии ТЗ `jfKfPfyJRdk` уже не работает), поэтому в каталоге лучше плейлисты, а стримы — как дополнение.

## 7. Риски
| Риск | Митигация |
|---|---|
| ~~YouTube не играет в WebView2 (ошибка 153, Referer, origin)~~ | Снят спайком T0: с `http://wails.localhost` всё играет, ошибки 153 нет |
| ~~Autoplay блокируется при автостарте фазы без клика~~ | Снят спайком T0: флаг `--autoplay-policy=no-user-gesture-required` (§5) |
| ID live-стримов в каталоге устаревают | Приоритет плейлистам, проверка каталога в плеере (T6), override через `genres.json` |
| Wails v3 ещё beta, API может поменяться | Логика в `internal/*` без Wails, версия зафиксирована в `go.mod` |
| Источники в каталоге пропадают или запрещают встраивание | Автопропуск по `onError` + override через `genres.json` |
